# Руководство по тестированию подключения к Supabase

## Обзор

В этом проекте реализована архитектура с возможностью переключения между реальным подключением к Supabase и mock-режимом с помощью переменной окружения `NEXT_PUBLIC_MEDIA_SOURCE`.

## Тестирование в режиме mock (без подключения к Supabase)

Для тестирования без подключения к реальной базе данных используйте mock-функции напрямую:

```bash
cd my_site_training
npx tsx test_supabase_mock_direct.ts
```

Этот тест проверяет:
- Получение данных по доменам (video, photo, partner, award)
- Получение URL медиа-файлов
- Получение элемента по ID
- Вставку, обновление и удаление элементов

## Тестирование с реальным подключением к Supabase

Для тестирования с реальным подключением к Supabase необходимо настроить переменные окружения:

### 1. Создайте файл `.env.local` в директории `my_site_training`:

```env
NEXT_PUBLIC_SUPABASE_URL=ваш_supabase_url
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_OR_ANON_KEY=ваш_anon_key
NEXT_PUBLIC_MEDIA_SOURCE=supabase
```

### 2. Затем можно запустить тест:

```bash
cd my_site_training
npx tsx test_supabase_connection.ts
```

## Структура тестов

Проект включает следующие файлы тестов:

1. `test_supabase_connection.ts` - тестирование подключения к реальной базе данных
2. `test_supabase_mock.ts` - тестирование в mock-режиме (не работает должным образом из-за особенностей переменных окружения в Node.js)
3. `test_supabase_mock_direct.ts` - тестирование mock-функций напрямую

## Архитектура подключения

### Уровни архитектуры:
1. **Presentation Layer** (UI Components)
2. **Application Layer** (MediaService)
3. **Data Access Layer** (media.ts)
4. **Infrastructure Layer** (media.supabase.ts, storage.supabase.ts)

### Переключение между реализациями:
- Используется переменная `NEXT_PUBLIC_MEDIA_SOURCE`
- При значении `'mock'`: используются mock-функции
- При значении `'supabase'` (по умолчанию): используются функции, подключающиеся к реальной базе данных

## Тестирование в браузере

При запуске приложения Next.js в браузере переменная `NEXT_PUBLIC_MEDIA_SOURCE` будет работать корректно:

```bash
cd my_site_training
npm run dev
```

Затем вы можете протестировать работу с медиа-данными через браузер, изменив значение переменной окружения и перезапустив сервер.

## Возможные проблемы и решения

1. **Ошибка "Your project's URL and API key are required"**:
   - Убедитесь, что переменные окружения `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_OR_ANON_KEY` установлены
   - В Node.js среде переменные `NEXT_PUBLIC_*` недоступны, поэтому для тестирования в mock-режиме используйте прямой импорт mock-функций

2. **Политики доступа к базе данных**:
   - Убедитесь, что политики доступа к таблице `media` настроены корректно
   - Проверьте файл миграции: `supabase/migrations/20250108140000_create_media_table.sql`

3. **CORS ошибки**:
   - В проекте используется прокси-роут `/api/supabase` для обхода CORS
   - Убедитесь, что API роут работает корректно

## Заключение

Для полноценного тестирования функциональности подключения к Supabase:
1. Используйте mock-режим для начального тестирования и разработки
2. Установите действительные учетные данные Supabase для тестирования с реальной базой данных
3. Проверьте работу через браузер, так как переменные окружения `NEXT_PUBLIC_*` работают корректно только на клиентской стороне
